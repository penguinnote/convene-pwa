# 새 행사에 앱 배포하기 — 단계별 가이드

이 문서 하나만 따라 하면 새 캠프용 앱을 처음부터 끝까지 만들 수 있습니다. **개발 경험이 없어도 됩니다.** 순서대로 하시고, 막히면 각 단계의 "막혔을 때" 항목을 보세요.

**총 소요 시간** 처음이면 3~4시간(대부분 기다리는 시간), 두 번째부터는 1시간 이내
**꼭 필요한 것** 노트북(맥·윈도우 무관), 구글 계정, **신용카드 1장**(아래 0-3 참고)

---

## 전체 흐름 한눈에 보기

```
[준비]  프로그램 설치 → 코드 내려받기
   ↓
[Firebase]  프로젝트 만들기 → 키 받아오기 → 결제 등록
   ↓
[연결]  .env.local 작성 → 프로젝트 이름 바꾸기
   ↓
[내용]  행사 정보 · 일정 · 말씀 입력
   ↓
[배포]  규칙 → 함수 → 웹사이트 순서로 올리기
   ↓
[마무리]  관리자 계정 만들기 → QR 만들기 → 테스트
```

**중요** 순서를 지켜주세요. 특히 배포는 반드시 **규칙 → 함수 → 웹사이트** 순입니다.

# 0. 준비

## 0-1. 프로그램 두 개 설치

**Node.js** — 앱을 만들 때 쓰는 도구입니다.

1. https://nodejs.org 접속
2. 왼쪽의 **LTS** 버튼 클릭해 다운로드
3. 설치 파일 실행, 계속 "다음" 누르면 됩니다

**Git** — 코드를 내려받고 저장하는 도구입니다.

- 맥: 터미널에 `git --version` 입력. 설치 안내가 뜨면 따라가면 됩니다
- 윈도우: https://git-scm.com/download/win 에서 받아 설치

## 0-2. 터미널 여는 법

앞으로 나오는 명령어를 입력하는 창입니다.

- **맥** — `⌘ + 스페이스` → `터미널` 입력 → 엔터
- **윈도우** — 시작 버튼 우클릭 → `터미널` 또는 `PowerShell`

> **터미널 사용 규칙**
> - 명령어를 **한 줄씩** 복사해 붙여넣고 엔터
> - 붙여넣기는 맥 `⌘V`, 윈도우 `Ctrl+V` (윈도우는 우클릭으로도 됩니다)
> - 비밀번호 입력 시 화면에 아무것도 안 보이는 게 정상입니다
> - 명령어가 실행 중이면 커서가 멈춰 있습니다. **기다리세요.** 다시 입력 가능해지면 끝난 겁니다

설치가 됐는지 확인합니다. 두 명령어 모두 버전 숫자가 나오면 성공입니다.

```bash
node -v
git --version
```

## 0-3. 신용카드가 필요한 이유

푸시 알림을 보내는 기능(Cloud Functions)은 Firebase의 **Blaze 요금제**에서만 동작합니다. 카드 등록이 필수입니다.

**하지만 실제로는 거의 무료입니다.** 100명 규모 4일 행사 기준으로 **월 0~1천 원** 수준입니다. 무료 사용량이 매우 넉넉해서 대부분 0원으로 끝납니다.

걱정되시면 **예산 알림**을 걸어두세요(아래 1-4).

# 1. Firebase 준비

Firebase는 구글이 제공하는 서비스로, 이 앱의 데이터 저장·알림 발송·웹사이트 호스팅을 모두 담당합니다.

## 1-1. 프로젝트 만들기

1. https://console.firebase.google.com 접속 → 구글 계정 로그인
2. **프로젝트 만들기** 클릭
3. 이름 입력 — 예: `rodemcamp-2027`
   - **영문 소문자·숫자·하이픈만** 사용하세요
   - 이 이름이 웹사이트 주소가 됩니다: `rodemcamp-2027.web.app`
   - 나중에 못 바꿉니다. 신중히 정하세요
4. Google 애널리틱스는 **사용 설정 해제**해도 됩니다 (앱이 자체 통계를 갖고 있습니다)
5. **프로젝트 만들기** → 1분 정도 기다립니다

## 1-2. 웹 앱 등록하고 키 받기

1. 프로젝트 첫 화면에서 **`</>`** (웹) 아이콘 클릭
2. 앱 닉네임에 아무 이름이나 입력 (예: `camp-web`)
3. "Firebase 호스팅 설정" 체크는 **하지 마세요**
4. **앱 등록** 클릭
5. 다음 화면에 이런 코드가 나옵니다. **이 화면을 캡처하거나 메모장에 복사해두세요.**

```js
const firebaseConfig = {
  apiKey: "AIzaSy...",
  authDomain: "rodemcamp-2027.firebaseapp.com",
  projectId: "rodemcamp-2027",
  storageBucket: "rodemcamp-2027.appspot.com",
  messagingSenderId: "123456789",
  appId: "1:123456789:web:abc123"
};
```

> 이 화면을 놓쳤다면: 좌측 상단 **⚙️ → 프로젝트 설정** → 아래로 스크롤하면 다시 볼 수 있습니다.

## 1-3. 알림 키(VAPID) 받기

푸시 알림에 꼭 필요한 값입니다.

1. **⚙️ → 프로젝트 설정** → 상단 **클라우드 메시징** 탭
2. 아래로 스크롤 → **웹 푸시 인증서** 항목
3. **키 쌍 생성** 클릭
4. 생성된 긴 문자열을 복사해둡니다 (`BN...`으로 시작)

## 1-4. 결제 등록 (Blaze 요금제)

1. 좌측 하단 **요금제 업그레이드** 또는 **Blaze로 업그레이드** 클릭
2. 결제 계정 만들기 → 카드 정보 입력
3. **예산 알림을 꼭 설정하세요** — 월 5,000원 정도로 잡아두면 초과 시 메일이 옵니다

## 1-5. 세 가지 서비스 켜기

좌측 메뉴에서 하나씩 켭니다.

**Authentication** (로그인)
1. **빌드 → Authentication** → **시작하기**
2. **익명** 선택 → 사용 설정 → 저장
3. **이메일/비밀번호** 선택 → 사용 설정 → 저장

**Firestore Database** (데이터 저장)
1. **빌드 → Firestore Database** → **데이터베이스 만들기**
2. **프로덕션 모드**로 시작 (나중에 규칙을 올릴 겁니다)
3. 위치는 **asia-northeast3 (서울)** 선택
4. 사용 설정

**Storage** (사진·파일 저장)
1. **빌드 → Storage** → **시작하기**
2. 프로덕션 모드 → 위치는 위와 동일하게

## 막혔을 때

| 증상 | 해결 |
|---|---|
| 프로젝트 이름이 이미 사용 중 | 뒤에 숫자를 붙이세요 (`rodemcamp-2027a`) |
| 웹 앱 등록 화면을 놓침 | ⚙️ → 프로젝트 설정 하단에서 다시 확인 |
| Blaze 업그레이드가 안 됨 | 구글 계정에 결제 프로필이 없는 경우입니다. 카드를 먼저 등록하세요 |

# 2. 코드 내려받고 연결하기

## 2-1. 코드 내려받기

터미널에서 한 줄씩 실행합니다.

```bash
cd ~/Documents
git clone https://github.com/penguinnote/convene-pwa.git camp-2027
cd camp-2027
npm install
```

`npm install`은 2~5분 걸립니다. 경고 메시지(`warn`)가 여러 줄 나와도 **정상**입니다. `error`가 아니면 넘어가세요.

## 2-2. 비밀 키 파일 만들기

1-2와 1-3에서 받은 값을 넣습니다.

```bash
cp .env.local.example .env.local
open .env.local          # 맥
notepad .env.local       # 윈도우
```

파일이 열리면 `=` 뒤에 값을 채웁니다. **따옴표는 넣지 마세요.**

```
VITE_FIREBASE_API_KEY=AIzaSy...
VITE_FIREBASE_AUTH_DOMAIN=rodemcamp-2027.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=rodemcamp-2027
VITE_FIREBASE_STORAGE_BUCKET=rodemcamp-2027.appspot.com
VITE_FIREBASE_MESSAGING_SENDER_ID=123456789
VITE_FIREBASE_APP_ID=1:123456789:web:abc123
VITE_FIREBASE_VAPID_KEY=BN...
VITE_FIREBASE_MEASUREMENT_ID=
```

마지막 줄은 비워둬도 됩니다. 저장하고 닫습니다.

> **이 파일은 절대 공개하면 안 됩니다.** GitHub에 올라가지 않도록 이미 설정돼 있으니, 그냥 두시면 됩니다.

## 2-3. 프로젝트 이름 바꾸기

`.firebaserc` 파일을 열어 프로젝트 ID를 새것으로 바꿉니다.

```json
{
  "projects": {
    "default": "rodemcamp-2027"
  }
}
```

## 2-4. Firebase 로그인

```bash
npx firebase-tools login
```

브라우저가 열리면 구글 계정으로 로그인하고 권한을 허용합니다.

## 막혔을 때

| 증상 | 해결 |
|---|---|
| `command not found: npm` | Node.js 설치가 안 됐습니다. 0-1로 돌아가세요 |

| `.env.local`을 열 수 없음 | 폴더에서 직접 찾아 메모장·텍스트편집기로 여세요. 숨김 파일일 수 있습니다 |

# 3. 행사 내용 채우기

여기서부터는 **파일을 직접 편집**합니다. 메모장보다 **VS Code**(https://code.visualstudio.com) 를 쓰시길 권합니다. 오류를 빨간 줄로 표시해줍니다.

> **⚠️ 가장 중요한 주의사항**
> 쉼표(`,`) · 따옴표(`"`) · 중괄호(`{}`)를 **하나라도 빠뜨리면 앱이 하얀 화면이 됩니다.**
> - 기존 내용을 **지우지 말고 값만 바꾸세요**
> - 한 파일 고칠 때마다 `npm run dev`로 확인하세요 (아래 3-5)
> - 문제가 생기면 `git checkout 파일이름`으로 되돌릴 수 있습니다

## 3-1. 행사 기본 정보 — `src/config/instance.js`

이 파일 하나가 앱의 이름·색·표어를 결정합니다.

| 항목 | 설명 | 예시 |
|---|---|---|
| `appName` | 홈 화면 아이콘 아래 이름 | `2027 여름말씀캠프` |
| `shortName` | 짧은 이름 | `말씀캠프` |
| `description` | 검색·공유 시 설명 | |
| `org` | 홈 상단 작은 글씨 | `2027 로뎀나무교회 청년대학부…` |
| `slogan` | 홈 큰 표어 | `아담아, 네가 어디 있느냐?` |
| `sloganEn` | 영문 표어 (이탤릭) | `Where are you?` |
| `expectedParticipants` | 등록 명단 인원 수 | `96` |
| `photosAlbumUrl` | 구글 포토 공유 앨범 주소 | |
| `liveAnchor` | **캠프 1일차 날짜** | `2027-07-28` |
| `theme.palette` | 브랜드 색상 | 아래 참고 |

**`liveAnchor`를 꼭 실제 캠프 첫날로 바꾸세요.** 홈의 "현재 순서" 카드가 이 날짜를 기준으로 계산합니다.

**색상 바꾸기** — `theme.palette.basil`의 `50`(가장 연함)부터 `900`(가장 진함)까지 10단계입니다. 포스터 대표색을 정한 뒤 https://uicolors.app/create 같은 도구에 넣으면 10단계를 자동으로 만들어줍니다.

## 3-2. 일정 — `src/data/schedule.js`

일자별로 `items` 배열에 순서를 넣습니다.

```js
{
  time: "14:00",              // 반드시 "HH:MM" 형식
  title: "등록 및 입소",
  place: "본관 로비",          // 없으면 ""
  link: { type: "schedule" }, // 아래 표 참고
},
```

`link`는 홈의 "현재 순서" 카드에서 어디로 이동할지 정합니다.

| type | 이동 위치 |
|---|---|
| `verse` | 말씀 본문 (`verseId`를 함께 지정) |
| `menu` | 식단표 — 식사 순서에 사용 |
| `playlist` | 플레이리스트 |
| `team` | 조 편성 |
| `resource` | 자료실(고정 공지) |
| `versesTab` | 말씀 탭 — **사용하지 않기를 권합니다** |
| `schedule` | 일정표 — **사용하지 않기를 권합니다** |

> 2026년 데이터: `schedule` 링크는 4일간 **0회**, `versesTab`은 3회 클릭됐습니다. 참가자는 하단 탭으로 직접 이동합니다. 새로 만들 때는 이 둘을 빼세요.

말씀으로 연결할 때는 이렇게 씁니다.

```js
link: { type: "verse", verseId: "topic-1" }
```

`verseId`는 다음 단계에서 만들 말씀의 id와 **정확히 일치**해야 합니다.

## 3-3. 말씀 본문 — `src/data/verses.js`

각 항목에 **고유한 `id`** 를 붙입니다. 기존 id 체계를 그대로 쓰시면 편합니다.

```
topic-1 ~ topic-5   주제 강의
opening / closing   개회 / 폐회
gbs-1 ~ gbs-3       GBS
dawn-1 ~ dawn-3     아침묵상
```

한글(개역개정)과 영문(NIV) 본문을 함께 넣습니다.

# 4. 배포하기

**반드시 이 순서대로** 실행합니다.

## 4-1. 보안 규칙 올리기

```bash
npx firebase-tools deploy --only firestore:rules,storage
```

가장 먼저 해야 합니다. 이걸 안 하면 앱이 데이터를 못 읽습니다.

## 4-2. 알림 발송 기능 올리기

```bash
cd functions
npm install
cd ..
npx firebase-tools deploy --only functions
```

3~5분 걸립니다. 처음이면 API 사용 설정을 묻는데 모두 **예**로 답하세요.

이 함수 두 개가 배포됩니다.

- `sendAnnouncement` — 공지가 등록되면 전원에게 푸시 발송
- `resendAnnouncement` — 공지를 수정하며 "다시 보내기"를 체크했을 때만 재발송

## 4-3. 웹사이트 올리기

```bash
npm run build
npx firebase-tools deploy --only hosting
```

성공하면 마지막 줄에 주소가 나옵니다. **이 주소가 앱 주소입니다.**

```
Hosting URL: https://rodemcamp-2027.web.app
```

| 증상 | 해결 |
|---|---|
| `Error: HTTP Error: 403` | `npx firebase-tools login` 다시 실행 |
| functions 배포 실패 | Blaze 요금제인지 확인(1-4). 무료 요금제면 배포되지 않습니다 |
| `Cannot find module` | `npm install` 다시 실행 |
| 배포는 됐는데 앱이 안 열림 | `.env.local` 값에 오타가 있는지 확인. 특히 `PROJECT_ID` |

# 5. 마무리 설정

## 5-1. 관리자 계정 만들기

공지를 쓰려면 이메일 계정이 필요합니다.

1. Firebase 콘솔 → **Authentication** → **Users** 탭
2. **사용자 추가** → 이메일·비밀번호 입력
3. 여러 명이 쓸 거면 **인원수만큼 만듭니다**
4. 앱에서 `/admin` 주소로 접속 → 그 계정으로 로그인

이 앱은 **이메일로 로그인한 사람 = 관리자**입니다. 참가자는 익명 로그인이라 이메일이 없어 관리자 화면에 들어올 수 없습니다.

> **계정을 아무에게나 주지 마세요.** 이메일 계정이 있으면 공지 작성·삭제, 참여자 정보 수정, 통계 조회가 모두 가능합니다.

## 5-2. 이전 데이터 지우기 (재사용하는 경우)

새 Firebase 프로젝트를 만들었다면 건너뛰세요. **기존 프로젝트를 재사용한다면** 이전 참가자 정보를 반드시 지워야 합니다.

Firestore Database → 각 컬렉션에서 문서 전체 삭제

| 컬렉션 | 지워야 하나 |
|---|---|
| `users` | **필수** — 이전 참가자 닉네임·프로필 사진 |
| `announcements` | **필수** — 작년 공지 |
| `events` | 권장 — 통계가 섞입니다 |
| `tokens` | **필수** — 안 지우면 작년 참가자에게 알림이 갑니다 |
| `config` | 권장 |
| `admins` · `pushLogs` | 권장 |

## 5-3. QR 코드 만들기

1. https://www.qrcode-monkey.com 등 아무 QR 생성 사이트 접속
2. 4-3에서 받은 주소 입력
3. 다운로드해서 **책자·이름표·포스터**에 넣습니다

> 2026년 설문에서 가장 많이 나온 요청이 "QR을 책자에 넣어달라"였습니다. 늦게 합류한 참가자가 앱을 못 깔았습니다.

## 5-4. 배포 전 최종 점검

휴대폰으로 실제 주소에 접속해 확인합니다. **아이폰과 안드로이드 둘 다** 봐주세요.

- [ ] 앱이 열리고 홈 화면이 정상인가
- [ ] 닉네임·목장 입력(온보딩)이 되는가
- [ ] **설치 안내 팝업**이 뜨는가
- [ ] 홈 화면에 추가한 뒤 앱으로 열면 팝업이 **안 뜨는가**
- [ ] 알림 권한을 허용할 수 있는가 (**아이폰은 홈 화면 설치 후에만 가능**)
- [ ] `/admin`에서 테스트 공지를 썼을 때 **다른 기기에 알림이 오는가**
- [ ] 일정·말씀·방배정·식단이 제대로 나오는가
- [ ] 홈의 "현재 순서"가 맞는 순서를 가리키는가 (`liveAnchor` 확인)

# 6. 행사 중 운영

배포 후 **재배포 없이** 관리자 화면에서 바꿀 수 있는 것들입니다.

| 기능 | 위치 | 설명 |
|---|---|---|
| 공지 작성·수정 | `/admin` | 작성 즉시 전원에게 푸시 |
| 고정 공지 | 공지 작성 시 "고정" 체크 | 홈 상단에 항상 노출 |
| 방배정 편집 | 관리자 → 방배정 | 저장 즉시 전원 반영 |
| 조 편성 관리 | 관리자 → 조 편성 | |
| 라이브 변동 메모 | 관리자 → 라이브 진행 | "점심 30분 지연" 같은 안내 |
| 참여자 관리 | 관리자 → 참여자 | 중복·오타 정리 |
| 통계 확인 | 관리자 → 통계 | 설치율·공지 열람·리텐션 |

## 공지 작성 요령 (2026년 데이터 기반)

**하루 3~4건을 넘기지 마세요.** 2026년에는 4일간 31건(하루 7.8건)을 보냈고, 응답자의 41%가 *"제목만 보고 넘겼다"* 고 답했습니다.

**제목만 읽어도 내용을 알 수 있게 쓰세요.** 많은 사람이 알림 배너의 제목만 보고 앱을 열지 않습니다. 제목이 곧 공지입니다.

- ❌ `저녁 안내` → ✅ `저녁식사 18:00 식당 (30분 지연)`
- ❌ `내일 일정` → ✅ `내일 기상 6:30, 아침묵상 7:00 대예배실`

**중요한 정보는 고정 공지로.** 2026년에 고정 공지는 **81%** 에게 도달했지만 일반 공지는 평균 **19%** 였습니다. 비상 연락망·와이파이·자료실처럼 계속 봐야 하는 건 고정하세요.

**일정 리마인더는 보내지 마세요.** 홈의 "현재 순서" 카드가 이미 그 역할을 합니다. 2026년 열람 하위 공지는 전부 일정 안내였습니다.

# 7. 자주 겪는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 아이폰에서 알림이 안 옴 | 홈 화면 설치를 안 함 | iOS는 **설치한 앱으로 실행한 상태에서만** 알림이 됩니다. 설치 안내 팝업을 따라 홈 화면에 추가하세요 |
| 공지를 써도 알림이 안 감 | functions 배포 누락 | 4-2를 다시 실행 |
| 앱이 하얀 화면 | 코드 문법 오류 | `F12` → Console에서 오류 확인 |
| 수정했는데 앱에 반영이 안 됨 | 배포를 안 함 | `npm run build` → `deploy --only hosting` |
| 배포했는데 옛날 화면이 보임 | 브라우저 캐시 | 앱을 완전히 닫았다 다시 열기. 그래도 안 되면 삭제 후 재설치 |
| 안드로이드에서 "유해할 수 있음" 경고 | 안드로이드 정책 | 앱 문제가 아닙니다. "무시하고 설치"로 진행하면 됩니다 |
| 관리자 화면에 못 들어감 | 익명 로그인 상태 | `/admin`에서 **이메일 계정으로** 로그인해야 합니다 |

## AI를 쓸 때 주의할 점

**AI가 틀린 답을 줄 수 있습니다.** 특히 Firebase 설정은 버전에 따라 화면이 자주 바뀝니다. AI 답과 실제 화면이 다르면 **이 문서와 Firebase 공식 문서를 우선**하세요.

**비밀 키를 붙여넣지 마세요.** `.env.local` 내용, API 키, 비밀번호는 AI에게 주면 안 됩니다.

**코드를 통째로 바꾸라는 제안은 조심하세요.** "이 파일을 이렇게 전부 교체하세요"라는 답변은 다른 기능을 망가뜨릴 수 있습니다. **값만 바꾸는 수정**을 요청하세요.
